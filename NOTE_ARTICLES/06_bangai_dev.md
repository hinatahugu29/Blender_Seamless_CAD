# 【番外】個人でB-RepカーネルをBlenderに載せた話

連載の本編では機能の話をしてきました。この記事は作り手側の話です。買うかどうかの判断には関係ありませんが、こういう構成で動いているという記録として書いておきます。

## そもそも何をやろうとしていたのか

やりたかったことは単純です。Blenderの中で、パラメトリックにモデリングしたい。

問題は、パラメトリックモデリングには幾何カーネルが要ることでした。押し出しやフィレットやブーリアンを、メッシュ近似ではなく数式の面として扱う部分です。ここを自分で書くのは、率直に言って現実的ではありません。商用CADが何十年もかけて磨いている領域です。

なので既存のカーネルを使うことにしました。OpenCASCADE（OCCT）です。オープンソースで、FreeCADなどでも使われています。

ここから先が問題でした。**OCCTはC++のライブラリで、Blenderのアドオンは Python です。**

## 3層構造になった経緯

最終的にこうなりました。

**Python層**がBlenderアドオンとして動きます。UI、フィーチャーツリーの管理、Blenderのデータとの同期。

**Rust層**が高速な演算を担当します。ドラッグ中のプレビュー用ブーリアン、GPUオーバーレイの描画。ネイティブモジュールとしてPythonから直接呼びます。

**C++層**、つまりOCCTを包んだプロセスが、正確なB-Rep演算を担当します。

三番目だけ、なぜプロセスを分けているのか。

理由は安定性です。CADカーネルをBlenderのプロセス内に直接埋め込むと、カーネル側で問題が起きたときにBlenderごと落ちます。ユーザーの作業中のファイルを巻き込むことになる。それは避けたかった。

なので別プロセスにして、ローカルのTCPソケット（127.0.0.1）で通信しています。多少のオーバーヘッドはありますが、Blenderが落ちないことのほうが重要だと判断しました。

## Rust側で何をしているか

いちばん効いているのは、ドラッグ中のプレビュー用ブーリアンです。

前の記事にも書きましたが、B-Repのブーリアンは正確なかわりに遅い。毎フレーム走らせると重すぎます。かといって、ドラッグ中に何も見えないのでは形が決められません。

そこで、BSP木を使ったメッシュベースの軽量ブーリアンをRustで書きました。ドラッグ中はこちらが毎フレーム結果を出し、指を離した瞬間にOCCTが正確な演算をやり直す、という役割分担です。

実測でOCCTのブーリアンより2桁速く、よくある切り欠き形状では水密性も保てることを確認しています。

2Dスケッチの拘束ソルバも Rust側です。こちらは自作ではなく、KittyCADが開発したezpzというクレートを使っています。拘束ソルバも自前で書くには重い領域なので、実績のある実装を借りました。

そのほか、GPUオーバーレイの描画にwgpu、並列化にrayonを使っています。

## 配布物を100MB以上削った話

OCCTを同梱すると、素朴にやると配布物が巨大になります。

OCCTの公式配布物には、QtやVTKといった可視化ツール用の依存が大量に含まれています。インスペクタや専用ビューアのためのもので、このアドオンはそれらを使いません。

なので段階的に外しました。Qt5が66ファイル111MB、NumPyが45MB、VTKとQtプラグイン類が222ファイル143MB。

ただし、**外すときは必ず「退避して回帰テストが通ること」を確認してから消しています。** 推測で消すと、特定の操作のときだけ落ちる、という最悪の壊れ方をします。

実際、外せなさそうに見えて外せないものがありました。FFmpegです。6ファイルで22MB。動画は一切扱っていないのに、cad_serverのロード時依存に入っていて、外すとカーネルが一切応答しなくなりました。実測でそう出たので、同梱を続けています。

最終的に、配布ZIPは約41MBに収まっています。大半はOCCT本体（84ファイル、62MB）です。利用者が別途インストールするものはありません。MSVCランタイムも同梱しています。

## UIの死んだ欄を機械的に検出する

これは地味ですが、効果が大きかった仕組みです。

長く作っていると、UIに表示されているのに実際には何にも効いていないパラメータ欄が発生します。仕様変更で使われなくなったのに、描画コードだけ残っている、というやつです。

これは利用者にとって最悪です。値を変えても何も起きないので、バグだと思われます。

なので、UIが描いている項目と、実際に形状計算で使われている項目を突き合わせて、不一致があれば失敗するスクリプトを書きました。これを走らせて見つかったのが、円柱と球のRadius欄、スロットや円錐の余剰なサイズ成分、クリーンアップのチェックボックス2つ。全部除去しました。現在は不一致ゼロです。

## テストが嘘をつく場面

ヘッドレス（GUIなし）の回帰テストも整備しています。ただ、これには罠がありました。

**プレビュー更新の処理が、GUIでは非同期、バックグラウンドでは同期で走ります。**

つまり、テストの中で「形を変えて、すぐに結果を読む」というコードを書くと、バックグラウンドでは同期実行なので正しく通ります。でも実際のGUIでは非同期なので、まだ計算が終わっていない古い結果を読むことになる。

テストが通るのに、利用者の環境では壊れている。いちばん質の悪い失敗です。

こういう罠は、踏んでから記録に残すしかありません。同じ種類の話として、開発中に古いカーネルプロセスが残っていると、新しいコードで追加したはずの操作が「エラーも出さずに何も返さない」という現象もありました。

## これから

現在ベータ版です。動いていますが、作りたいものにはまだ届いていません。

いま優先度が高いと思っている項目を挙げておきます。

- 寸法線を、数値ラベルではなくCADの製図らしい表現にする
- STEP書き出しに形状名を含める（ライターの差し替えで可能）
- SolidWorksなど別カーネルの実装でのSTEP検証結果を公開する
- Windows以外への対応。LinuxとApple Siliconはビルドとパッケージングまでは通っていて、残っているのは署名と実機での検証です

本編の各記事に書いた「できないこと」も、そのまま作業リストです。

もし使ってみて詰まったところがあれば、それがいちばん有用な情報です。教えてください。

### Seamless CADについて

Blenderの中でパラメトリックモデリングをするためのアドオンです。押し出しやフィレットが履歴として残り、あとから数値を書き換えると部品全体が組み直ります。内部はB-Rep（OpenCASCADE 8.0.1）で、メッシュ近似ではありません。

現在**ベータ版**です。動作は安定していますが機能は増えている途中で、できないこともあります。各記事の中で、その回の機能について「できないこと」も正直に書いています。

対応環境：Blender 4.2以降 / Windows
