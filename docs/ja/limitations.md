# 既知の制約

このページは意図的に率直に書いています。**大事なものを作ってから気づくより、先に
知っておいたほうがいい**内容です。

## ベータ版

Seamless CAD はベータ版です。バージョン間で挙動が変わることがありますし、落ちる
こともあります。こまめに保存してください。

## Windows 専用

製品として動作するのは **Windows のみ**です。形状カーネルを Windows 向けにビルド
した実行ファイルとして同梱しているためです。

**Linux (x86-64)** と **macOS (Apple Silicon)** のビルドはあり、テスターの方に
お渡ししています。販売はしておらず、リリース時期も未定です。Intel Mac 版は
ありません。何が確認済みで何が未確認かは [テストビルド](testing-builds.md) に
書いていますが、要点は**まだ誰も Blender の中で動かしていない**ということです。

リリースまでに残っているものは、アドオンの Python コードではありません。

- **macOS は公証を通していません。**カーネルは ad-hoc 署名のみです。公証には
  Apple Developer Program への登録が必要ですが、現時点でその費用を確保できて
  いません。**これが正直な理由**であり、macOS 版リリースの主な障壁です
- **実機で確認できたことが何もありません。**ビューポートが Metal 経由で
  そもそも描画できるのかは、自動ビルドでは確かめようがありません
- Linux は glibc 2.34 が実質の下限です（Ubuntu 22.04、Debian 12、RHEL 9 以降）

## Blender のバージョン

Blender 4.2 以降。開発と動作確認は 5.1 で行っています。その間のバージョンでも動く
見込みですが、検証は手薄です。

本アドオンは **Extension ではなく従来形式のアドオン**として配布しています。zip に
`blender_manifest.toml` は入っていないため、ドラッグ＆ドロップでのインストールや
Extensions リポジトリには対応しません。`ディスクからインストール…` を使ってください。
[インストール](install.md) を参照してください。

## Feature Tree は並べ替えられない

順序は作成順です。行を上下に移動することはできず、既存の履歴の途中に新しい操作を
挿し込むこともできません。新しい項目は常に末尾に追加され、ロールバックのピンを
刺していても同じです。

これは作業の進め方に対する実際の制約です。順序は組み立てながら決めることに
なります。代わりに何をするかは [Feature Tree と Part](feature-tree.md) にあります。

## 書き出したファイルに色は入らない

STEP 書き出しはパーツ名とアセンブリ構造を書き込みますし、形状は AP214 IS の
厳密な B-Rep です。**欠けているのは色だけ**で、その理由は書き出し側ではなく
その手前にあります。このアドオンには Part にも面にも色を設定する場所がないため、
ファイルに運ぶ元の色が存在しません。

受け取る側が「色分けされたアセンブリ」を必要としているなら、現時点の書き出しでは
その要求を満たせません。

IGES 書き出しはさらに手前で、**形状のみ**です。名前も構造も入りません。これは
意図的なもので、IGES は名前の扱いが読み手によって食い違いすぎるためです。
受け取る側が STEP を読めない場合を除き、STEP を使ってください。

## STEP 書き出しの単位

**既定では 1 Blender 単位が 1 mm** として書き出されます。別の基準で作っている
場合は、書き出しダイアログの *Scale (1 unit = N mm)* を使ってください。
1 単位がメートルなら 1000、センチメートルなら 10 です。読み込み側の Scale と
同じ意味なので、10 で取り込んだファイルは 10 で書き出せばそのまま戻ります。

1.0 のままにしておけば、これまでの版と同じ挙動です。

## Inset は平らな面が必要

**曲面に Inset をかけても何も起きません** — 円柱や円錐の側面です。面の境界を
内側へオフセットする処理が平面を前提にしており、曲面では結果が出ません。
何も起きず、エラーも出ません。

円柱・円錐の平らな上面と底面、そして箱のすべての面では問題なく動作します。

## Cleanup (Unify) は参照を壊す

同一平面上の面を統合すると、Fillet・Chamfer・Offset・Shell・Draft が依存している
面の同一性が失われます。自動適用されないのはこのためで、生きた履歴の途中で適用
すると、それより下の操作を壊すことがあります。

**書き出し直前の最終工程として扱ってください。**[仕組み](concepts.md) を参照。

## 形状計算は同時に1つの Blender しか行えない

形状計算は別プロセスのカーネルが行い、Blender はローカルの固定ポート経由でそれと
通信します。**最初に起動した Blender がそのポートを掴みます。** アドオンを有効にした
2つ目の Blender を開くと、自分専用のカーネルを起動せず、すでに動いているカーネル
（別ファイルの形状を保持している）へ接続します。その結果、どちらか一方または両方で
プレビューが正しく更新されなくなります。

参考用に2つ目の Blender を開いておく、というのは普通の使い方なので、これは実際に
問題になります。

Blender ごとに専用のカーネルを持たせるまでの回避策は次のとおりです。

- 参考にするファイル側で **Bake to Mesh** する（カーネルが不要になります）
- 見るためだけに開いている Blender ではアドオンを無効にする
- 片方の Blender を閉じてから、もう片方で作業を始める

これで壊れるのはライブプレビューだけです。**保存済みのデータは壊れません。**

## ベイクしたメッシュはリンクされない

**Bake to Mesh** が作るのはスナップショットです。Feature Tree を変更しても更新
されません。もう一度ベイクする必要があります。

## 履歴の前半の編集は高くつく

長い Feature Tree の上のほうの操作を変更すると、それより下をすべて計算し直す必要が
あります。これは不具合ではなく履歴ベース CAD の本質ですが、**1つのパーツをどこまで
大きくできるかの実際的な上限**にはなります。

緩和策はロールバックポイントと、複数パーツへの分割です。
[品質とパフォーマンス](quality.md) を参照。

## Blender のメッシュツールは効かない

CAD 形状は Blender のメッシュ機能ではなくカーネルが計算しています。そのため Blender
のモデリング、スカルプト、モディファイアは直接は作用しません。先に **Bake to Mesh**
を通してください。

## ドキュメントの対応範囲

英語版が完全で、これが正本です。日本語版は英語版に追随しています。ロシア語版と
中国語版は**クイックスタートのみ**で、しかもその2言語は**AI が翻訳し、母語話者の
校閲を受けていません。**各ページ冒頭にその旨を明記しています。
