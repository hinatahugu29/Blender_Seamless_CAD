Frequently Asked Questions (FAQ)

Q1: Which operating systems are supported?

A: Windows 10 / 11 (64-bit), Linux x86-64, and macOS on Apple Silicon. All three are in the one download; pick the file for your platform by its name.

They are not equally proven, and it matters which one you are on. Windows is what the add-on is developed and tested on: 51 headless checks run against it on every change, and the manual checks that need a real screen are done there. Linux and macOS are built by the same automated pipeline from the same source, against the same version of the geometry kernel — the build verifies that each compiles, bundles its libraries, starts, answers, and is packaged complete. Nothing beyond that has been confirmed. The test suite has never been run on either, and no individual feature has been verified in Blender on a Mac or a Linux machine by the developer. Several users have reported them running, which is why they are now included rather than handed out as test builds, but none recorded how far they got.

So: if you are on Windows, buy normally. If you are on Linux or macOS, you are getting something that should work and is built with the same care, but that has not been proven the way the Windows build has — and a report from you is worth a great deal.

Two hard limits. Intel Macs are not supported — Apple Silicon only. On Linux the build needs glibc 2.34 or newer (measured; that means Ubuntu 22.04, Debian 12, RHEL 9 or later), which is not far from what Blender itself asks for.

Q1b: I am on a Mac. Will macOS let this run?

A: Probably, and there is a one-line fix if it does not.

The kernel is signed, but only ad-hoc — it has not been through Apple's notarisation, because that needs a paid Apple Developer membership that is not funded yet. That is the honest state of it, and it is the reason macOS took as long as it did to appear here at all.

In practice it often runs regardless: Blender extracts the zip itself, and files unpacked that way do not normally carry the quarantine flag that triggers the check. If the add-on loads but no geometry ever appears, clear the flag and restart Blender:

xattr -dr com.apple.quarantine ~/Library/Application\ Support/Blender/*/scripts/addons/CAD_8_1_5_1

Please tell me which of the two happened to you — whether you needed that command or not. It cannot be determined from here, and it decides whether this stays a footnote or becomes a step in the install instructions.

Q2: Which Blender versions are compatible?

A: Blender 4.2 LTS through 5.1. Tested on 4.2, 4.3, 4.4 and 5.1.

A user has since reported it running on 5.2 as well. That is one person's report rather than testing done here, so 5.2 is not on the supported list — but nothing is known to be broken on it.

Q3: Which file formats can it read and write?

A: STEP import and export, and SVG import for 2D profiles. STEP is the format that matters for moving real solids to and from SolidWorks, Fusion 360, Rhino or FreeCAD, and on to CNC or 3D printing. IGES is not supported. You can also bake any result to a normal Blender mesh and use Blender's own exporters from there.

Two things to know about STEP export specifically: 1 Blender unit is written as 1 mm and there is no export scale option, so build at millimetre scale; and the file carries geometry only — no part names, no colours, no assembly structure. The surfaces themselves are exact, not triangulated. STEP import does have a scale option.

Q4: Do I need separate CAD software or licenses installed?

A: No. The CAD kernel (OpenCASCADE) and everything it needs are bundled with the add-on. No third-party CAD licenses, and no separate runtime to install.

Q5: What does "Beta" actually mean here?

A: It works, and it is being used for real modeling — but it is still under active development. Expect rough edges, expect behaviour to change between updates, and please save your work. Bug reports genuinely shape what gets fixed next. The launch price reflects this stage.

Q6: Are future updates included with my purchase?

A: Yes. All updates in the 8.x series are included free of charge.

Q7: Is the source code available?

A: Yes. Blender add-ons are GPL, and this one is no exception — it ships under the GNU GPL v2 or later, and the source, including the Rust and C++ geometry kernel, is published openly. You are free to read it, learn from it and modify it.

Q10: Will it change my keymap? I use the Industry Compatible one.

A: It registers no keymap entries at all, so nothing you already use in Blender is rebound or overridden.

The part worth knowing is that the add-on's interactive modes — sketching, selection, transform — run as modal operators, and while one is running it handles keys itself. Viewport navigation is passed through, so middle mouse, the wheel and the numpad views keep working without leaving the mode. As of 8.1.5.8 the Industry Compatible keymap is passed through too, meaning Alt with a mouse button orbits, pans and zooms from inside a mode.

One overlap remains by design: in Selection Mode, Alt + left drag is also how you move a gizmo axis. It resolves by what is under the cursor — on a gizmo axis or a control point you grab it, anywhere else you orbit.

If you find a navigation key that a mode swallows, please report it. That is a bug, not intended behaviour, and the 8.1.5.8 fixes came from exactly such a report.

Q11: Faces and edges light up when I hover, but I cannot select them. What am I missing?

A: Add the modifier first, then pick. Press Fillet (or Chamfer, Shell, Draft, Offset, Inset) and Selection Mode starts on its own, already set to edges or faces as that modifier needs. Click from there and the picks stick.

A selection is stored inside the modifier, so until one exists there is nowhere to put it. Entering Selection Mode with an ordinary box or cylinder active and clicking selects nothing — the hover highlight still follows the cursor, which makes it look as though selection is broken rather than out of order.

Two things changed in 8.1.5.9 because of this: the add-on now tells you what it needs instead of ignoring the click, and the Quick Start — which had the two steps the wrong way round, and was the reason people ran into it — has been corrected.
